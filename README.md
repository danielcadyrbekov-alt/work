# Map layers panel

Небольшой интерфейс управления картографическими слоями (температура, ветер,
инсоляция) на React + TypeScript, со стейт-менеджментом на
[`vedro`](https://www.npmjs.com/package/vedro).

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run test     # тесты (vitest)
npm run build    # проверка типов + production-сборка
```

## Что реализовано

Для каждого слоя:

- включение / выключение;
- регулировка прозрачности (opacity);
- статус: `idle / loading / success / error`;
- повторная загрузка после ошибки (Retry);
- имитация запроса к API через mock (`layerApi.ts`, случайная задержка
  500–1200мс, ~30% ошибок).

## Структура

```
src/
  layers/
    types.ts                # доменные типы (LayerState, LayersStoreState)
    layerConfig.ts           # список слоёв — единственное место для их добавления
    layerApi.ts               # mock-запрос
    store.ts                  # createVedro() — типизированный стор
    useLayerController.ts     # логика одного слоя: toggle/opacity/retry + race condition
    useLayerController.test.tsx
  components/
    LayerPanel.tsx            # рендерит по одной строке на слой из layerConfig.ts
    LayerRow.tsx               # UI одного слоя, подписан только на свой кусок стора
    LayerRow.test.tsx
```

## Управление состоянием (vedro)

`createVedro(initialState)` создаёт React-контекст и набор хуков
(`useSelector`, `useDispatch`, `useStore`) вокруг одного объекта состояния.
Весь стор — это `{ layers: Record<LayerId, LayerState> }`.

Ключевая деталь реализации `useSelector` внутри `vedro`: он подписывается на
каждое изменение стора, но вызывает `setState` (а значит и ре-рендер) только
если результат селектора **действительно изменился по значению**. Поэтому:

```ts
const layer = useLayersSelector((state) => state.layers[id]);
```

— компонент одного слоя не перерендеривается при изменении любого другого
слоя. Это и даёт масштабируемость: при 100+ слоях обновление одного из них
затрагивает ровно один компонент.

## Race condition при быстрых переключениях

Каждый запрос за данными слоя помечается инкрементным номером (`epoch`),
который хранится в `useRef` внутри `useLayerController`. Когда промис
резолвится, проверяется, остаётся ли этот запрос последним:

```ts
if (latestEpoch.current !== epoch) return; // ответ устарел — игнорируем
```

Если слой быстро выключить и снова включить (или нажать Retry) до того, как
пришёл предыдущий ответ, старый (более медленный) ответ будет отброшен и не
перезапишет состояние, установленное новым запросом. Счётчик специально
живёт в `useRef`, а не в глобальном сторе — это деталь реализации
асинхронности, а не то, что должно быть видно другим компонентам.

`dispatch` в `useLayerController` передаётся параметром, а не берётся из
стора напрямую — это позволяет тестировать хук в изоляции, на отдельном
тестовом сторе `vedro`, без рендера всего дерева компонентов.

## Масштабирование с 3 до 100+ слоёв

Единственное место, которое нужно менять, чтобы добавить слой —
`layerConfig.ts`:

```ts
export const LAYER_DEFINITIONS = [
  { id: 'temperature', label: 'Температура' },
  { id: 'wind', label: 'Ветер' },
  { id: 'insolation', label: 'Инсоляция' },
  // ...
];
```

`store.ts`, `LayerPanel` и `LayerRow` работают с произвольным набором id и
не меняются при добавлении новых слоёв.

## Типизация

Проект не использует `any`. Типы стора и dispatch выведены из самого пакета
`vedro` (`Vedro<LayersStoreState>['dispatch']`), без ручного дублирования.
